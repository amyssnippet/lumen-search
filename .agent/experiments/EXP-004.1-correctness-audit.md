## 1. Motivation & Audit of Previous EXP-004 Defects

A code review identified six specific discrepancies in EXP-004:
1. **Ambiguous Fusion Parameter**: Previous code used `alpha` with conflicting semantics across docstrings and code (`alpha * g_score + (1 - alpha) * ch_score` vs reversed patch weights). The API silently passed `alpha = 0.3`.
2. **Defective Score Normalization**: RRF scores were previously divided by `max_rrf` (the leading candidate's score). This query-relative scaling distorted absolute similarity and failed to guarantee bounds or calibrated meaning.
3. **Invalid Threshold Transfer**: Fixed single-model cosine thresholds ($\tau = 0.94$) were directly applied to fused Chamfer-RRF scores, and items were prematurely labeled "Verified Exact SKU / Twin" without ground truth verification.
4. **Asymmetric Background Masking**: Query foreground was masked, but candidate patches were matched over the full $16 \times 16$ grid (including 80%+ studio white background patches), diluting distinctive prong/gemstone features.
5. **Transitive Ground-Truth Error on `ring_083`**: `ring_083` was assigned to `cluster_010` via a transitive union-find chain in perceptual hash space (`ring_083` $\to$ `ring_116` $\to$ `ring_187`, with an effective distance of 6 bits / 4 hex characters). Visually, `ring_083` is a round solitaire, whereas `ring_187` has pavé shoulders.
6. **Inconsistent Diagnostics**: Timing fields varied across models, and intermediate inference latencies were combined rather than reported individually.

## 2. Corrected Implementations & Formulations

### Phase 1: Unambiguous Fusion Formula
All signatures, engines, APIs, and scripts standardized on `patch_weight`:
$$\text{final\_score} = (1 - \text{patch\_weight}) \cdot \text{normalized\_global\_score} + \text{patch\_weight} \cdot \text{chamfer\_score}$$
- $\text{patch\_weight} = 0.0$: global score only.
- $\text{patch\_weight} = 1.0$: Chamfer score only.
- Default deployed configuration: $\text{patch\_weight} = 0.2$ (or $0.5$).

### Phase 2: Dual-Model Cosine Score Normalization
Instead of dividing by the query's maximum RRF score, the normalized global score is computed from the dual visual embeddings:
$$S_{\text{global}}(c) = \frac{1}{2} \left( \cos(\mathbf{q}_{v2}, \mathbf{c}_{v2}) + \cos(\mathbf{q}_{v3}, \mathbf{c}_{v3}) \right)$$
Because both components are authentic cosine similarities on unit hyperspheres, fusing them with Chamfer patch similarity preserves consistent units and physical meaning.

### Phase 3: Symmetric Foreground-Masked Chamfer & Spatial Constraint
1. **Symmetric Masking**: Foreground patch indices are computed for both query and candidate using `get_foreground_patch_indices()`.
   $$\text{Chamfer}(Q, C) = \frac{1}{2} \left( \frac{1}{|Q_{\text{fg}}|} \sum_{i \in Q_{\text{fg}}} \max_{j \in C_{\text{fg}}} S_{i, j} + \frac{1}{|C_{\text{fg}}|} \sum_{j \in C_{\text{fg}}} \max_{i \in Q_{\text{fg}}} S_{i, j} \right)$$
2. **Degenerate Mask Fallbacks**: If either mask has $< 4$ patches, it safely falls back to all 256 patches.
3. **Spatial Distance Penalty**: An optional spatial weight $\lambda \ge 0$ penalizes matches between spatially incompatible grid positions:
   $$S_{i, j}^{\text{spat}} = S_{i, j} - \lambda \cdot \frac{\sqrt{(r_i - r_j)^2 + (c_i - c_j)^2}}{\sqrt{2 \cdot 15^2}}$$
4. **Versioned Patch Cache**: Created `data/index/dinov3_patches.meta.json` storing manifest SHA-256, version 1.1.0, row-to-ID alignment, and precomputed catalog foreground masks for all 432 catalog items.

### Phase 4: Calibrated Confidence Policies
Independently calibrated on 100 held-out catalog items (photometrically/geometrically augmented) vs 300 negative pairs from disjoint clusters:
- **DINOv2**: Pos $0.9825 \pm 0.0107$, Neg $0.4372 \pm 0.2322 \implies \tau_{95\%} = 0.880, \tau_{99\%} = 0.905$
- **DINOv3**: Pos $0.9927 \pm 0.0029$, Neg $0.7924 \pm 0.0955 \implies \tau_{95\%} = 0.965, \tau_{99\%} = 0.970$
- **Hybrid Global**: Pos $0.9876 \pm 0.0062$, Neg $0.6148 \pm 0.1544 \implies \tau_{95\%} = 0.915, \tau_{99\%} = 0.935$
- **Hybrid Rerank ($\text{pw}=0.2$)**: Pos $0.9853 \pm 0.0062$, Neg $0.6308 \pm 0.1427 \implies \tau_{95\%} = 0.910, \tau_{99\%} = 0.935$

Candidate confidence labels are strictly qualified as **unverified**:
- $\ge \tau_{\text{exact}}$: `"High-Confidence Candidate Match"`
- $0.75 \le \text{sim} < \tau_{\text{exact}}$: `"Visually Similar Candidate"`
- $< 0.75$: `"Low Confidence Candidate"`
